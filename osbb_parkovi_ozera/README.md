# Система управління житловим фондом ОСББ — ЖК «Паркові Озера»

Внутрішній інструмент диспетчера, майстрів і правління: облік заявок на ремонт, персоналу та підрядників,
матеріалів, оплат (двостороння модель) і аналітичні звіти з експортом у CSV.
Qt 6 (Widgets) + C++17 + SQLite (QSQLITE). Без мобільного застосунку й кабінету мешканця.

## Збірка
- Qt ≥ 6.5 (перевірялось на планованій збірці Qt 6.12, MinGW 64-bit), CMake ≥ 3.19, Qt Creator.
- Відкрийте `CMakeLists.txt` у Qt Creator → оберіть комплект Desktop Qt → Configure Project → Build & Run.
- Модулі Qt: Widgets, Sql (драйвер SQLite входить до стандартної збірки).

## Розділи
- **Головна** — відкриті заявки, аварійні/термінові, заборгованість, баланс загального фонду.
- **Об’єкти / Заявки на ремонт** — спільне майно, під’їзди, прибудинкова територія, квартири; джерело (Telegram-чат вводиться вручну), пріоритет, статус, виконавець, терміни.
- **Списання матеріалів** — залишок на складі змінюється тригерами; джерело коштів: загальний фонд або власник квартири.
- **Оплати** — рахунок «Загальний фонд» (цільові внески) та «Індивідуальний» (власники); кнопка «Рахунок власнику» формує рахунок за заявкою: вартість робіт + матеріали за рахунок власника + доплата.
- **Доплати та виклики** — тарифи платних виїздів/спецбригад (сума підставляється в оплату автоматично).
- **Довідники** — Персонал та підрядники, Квартири та власники, Матеріали (склад), Види робіт та послуг (кошторисні норми).
- **Звіти** — 8 звітів за період із підсумками та експортом у CSV (UTF-8 з BOM, роздільник «;»).

Зміни в таблицях накопичуються й записуються кнопкою «Зберегти» (нові рядки — зелені, змінені — жовті, видалені — червоні).

## База даних
Файл `parkovi_ozera.db` створюється поруч із exe зі вбудованих `sql/schema.sql` та `sql/seed.sql`.
Таблиці (8): `матеріали`, `види_робіт`, `персонал_підрядники`, `квартири`, `заявки`, `списання_матеріалів`, `доплати`, `оплати`.
Розрахункові поля (`сума`, `борг`) — GENERATED-стовпці; контроль даних — CHECK, UNIQUE, зовнішні ключі.
Версія схеми — `PRAGMA user_version = 2`: якщо знайдено стару БД («Бюро ремонту»), її копія зберігається як
`parkovi_ozera_old_<дата>.db`, а створюється нова.

**Увага:** схему свідомо розширено порівняно з попередньою версією (5 таблиць, договір → 8 таблиць без договору).
Опис у пояснювальній записці має відповідати саме цій схемі.
Демонстраційні дані (мешканці, телефони, суми) — вигадані, для тестування.
